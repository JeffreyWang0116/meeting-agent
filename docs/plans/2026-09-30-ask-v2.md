# 詢問會議 v2：AI 解析條件、列出相關段落、出處可跳逐字稿

日期：2026-09-30

## 決策紀錄（使用者 2026-09-30 核准）
- 要解決：出處可點並跳到逐字稿那一行、列出相關會議與段落、聽懂時間／種類／人名條件
- 額度：每次提問最多 2 次 Gemini 生成（解析條件＋回答），檢索本身不花生成額度
- 條件篩完一場都沒有 → 直接回「沒有符合條件的會議」並顯示條件，不打第 2 次、不放寬硬找
- 解析失敗（格式錯、額度）→ 不套條件照常檢索，不讓整個提問失敗
- 手動勾選範圍時，在勾選範圍內再套 AI 條件

## 架構
```
ask(question, meeting_ids)
  sync 索引 → 沒有任何會議：直接回訊息（0 次生成）
  ① plan = parse_plan(generate(plan_prompt))    # 失敗 → AskPlan(query=question)
  candidates = scope ∩ filter_meetings(plan)     # 有條件且為空 → 回「沒有符合…」（1 次生成）
  hits = 語意 top 8 ∪ 關鍵字命中（去重，上限 10）
  ② generate(answer_prompt 帶 [編號] 片段) → {"answer", "cited": [編號]}
  回 {answer, sources, passages[{meeting_id,title,date,time,text,cited}], conditions}
```

## 任務（TDD）
1. `app/ask_planner.py`：`AskPlan`、`build_plan_prompt`、`parse_plan`（未知種類丟掉、日期顛倒對調、
   壞 JSON 回預設）、`filter_meetings`（日期／種類含舊種類對應／人名＝出席者、任務負責人、講者欄）
   → `tests/test_ask_planner.py`
2. `rag.py` 逐字稿依行切塊、記第一個時間戳；記錄加 `source`（summary／transcript）與 `time`；
   缺 `source` 的舊索引載入時作廢重建；`keyword_search`
3. `AskAgent.ask` 串起兩次呼叫、條件篩選、混合檢索、引用解析；更新 `tests/test_rag.py`
4. `main.py`：傳入今天日期與種類清單
5. 前端 `ask.js`：條件標籤、依會議分組的段落清單、點擊開會議並跳逐字稿
6. README、全套測試＋ruff＋瀏覽器實測
