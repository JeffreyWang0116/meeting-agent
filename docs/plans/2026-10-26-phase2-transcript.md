# 第二階段：逐字稿編輯、即時聆聽、處理進度

日期：2026-10-26　分支：`phase2-transcript`

## 決策紀錄（使用者 2026-10-26 核准）
- #6 原本的「保留錄音＋點逐字稿播放」取消：使用者選不保留錄音；點重點／引用句跳轉本來就有
- #7 編輯逐字稿：前端送**整份**逐字稿回後端（泡泡是多行合併出來的，行號對不回原文）
- 編輯後引用原句可能跳不回去——小修不受影響（比對會縮短前綴重試），大改靠「重新分析」
- 即時聆聽進行中不給編輯（新段落還在往後接）
- #16 不做「聆聽中問 AI」：每問一次吃額度，開會中也沒空打字；等第三階段的結果頁對話再看
- #23 完成通知用現有的 Notification API（頁面要開著）；離線推播在第四階段

## 任務（每項先寫失敗測試）
1. **後端：逐字稿編輯的安全驗證**。`PATCH /api/meetings/{id}` 的 transcript 加驗證：時間標記數量不得減少（防整段誤刪），否則 400。既有的 drop_from_rag 已會作廢索引
2. **前端：就地編輯一句**。逐字稿每句一個編輯鈕 → 文字輸入框、講者下拉（這場已有的講者＋自訂）。送出時由泡泡重建整份逐字稿文字
3. **前端：合併與拆句**。相鄰兩句合併；游標處拆成兩句
4. **前端：改完重新分析**。編輯過就出現「用修正後的逐字稿重新分析」，走既有 reanalyze
5. **即時聆聽段長可選**：前端 20/30/45/60 秒，選項旁標「一小時約 N 次請求」；`POST /api/live/start` 接受 chunk_seconds（夾在合理範圍）
6. **⭐ 標記這一刻**：聆聽中記下時間點，可取消；結束分析時把時間點送進 decision_agent 當「優先列入會議重點」的提示
7. **聆聽中打字記筆記**：與逐字稿一起送分析，明確標示是人工筆記而非逐字稿
8. **iOS 背景錄音警告**：頁面離開前景超過數秒 → 回來時明確警告可能沒錄到
9. **轉錄預估剩餘時間**：依已完成段數與平均耗時推算
10. **完成通知＋分頁標題進度**：頁面不在前景時發 Notification；標題顯示 (45%)
11. README、完整測試、瀏覽器驗證

## 實作時與計畫不同之處
- #6 確認無事可做：不保留錄音，而「點重點／引用句跳到逐字稿」本來就有
- 任務 1（後端驗證時間標記數量不得減少）取消：合併兩句本來就會少一個時間標記，
  這條規則會擋掉正當操作。改成把風險收在前端——泡泡記住自己來自原文哪幾行，
  只換那幾行，並用 node 測試釘住切分規則
- 任務 2~4 額外做了：parseChatMessages 從 transcript.js 移到 transcriptedit.js，
  渲染與編輯共用同一份切分（兩邊各切一次遲早會不一致，編輯就會改到別句）
- 任務 5 不需要動後端：段長本來就是前端決定的
- 任務 6、7 的標記與筆記，連 `/api/meetings` 也一起支援——聆聽 session 遺失時
  會改走那支端點救援，使用者打的筆記不該跟著不見
- 額外：修掉 hidden 屬性被元件自己的 display 蓋過的老問題（全域 [hidden] 規則，
  移除散落各處的 11 條個別修補）
- 本機原本跑不到前端 JS 測試（沒裝 node）。改用 Playwright 內建的 node：
  PATH="$PWD/.venv/Lib/site-packages/playwright/driver:$PATH" pytest

# 第三階段：AI 品質（同一份文件續記）

分支：`phase3-ai`。項目：#8 請 AI 修改、#9 自訂範本、#26 錯誤回報、#27 信心標示、#28 日期原話。

## 決策紀錄（使用者 2026-10-26 授權由實作者決定）
- #8 採「先預覽再套用」：AI 默默改掉摘要或負責人，使用者不會發現——與當初整條
  移除「讓模型猜講者姓名」同一個理由。套用那一步不打 AI，所以不佔 refine 額度
- #26 用「固定六種原因 ＋ 選填文字」：原因固定才統計得了、篩得出案例；
  正確答案選填，不想打字的人按兩下就好
- #27 不另外問模型「你有多確定」（那個數字不可靠），改用既有的客觀證據：
  代辦沒有 source_quote、逐字稿有轉錄缺漏標記
- #9 範本存在工作區底下（user 欄位），群組自動共用；kind 值用 custom:<id>

## 實作時值得記的
- build_prompt 新增 kind_spec 參數：有值就取代內建種類的查表，其餘流程完全一樣
- 刪掉範本不能弄壞舊會議：重新分析退回通用格式；編輯時只要沒換種類就放行
